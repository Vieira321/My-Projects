# The Twelve-Factor App

> Example source page — shows how a raw note is compiled into the wiki.

## Thesis
A methodology of twelve principles for building portable, scalable
software-as-a-service applications.

## Key Claims
- Configuration belongs in the environment, never in the codebase.
- Backing services (DBs, queues, caches) should be treated as swappable attached resources.
- Build, release and run stages must be strictly separated.
- App processes should be stateless and share-nothing.
